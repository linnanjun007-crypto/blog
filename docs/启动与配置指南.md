# 2025 Blog 启动与配置指南

> 一份写给「想把这个博客改成自己用」的人的中文说明。本仓库是一个**无后端**的 Next.js 个人博客：内容以静态文件形式存在仓库里，网站前端通过 GitHub API 直接把改动写回 GitHub 仓库。你不需要数据库，也不需要自己写服务端。

---

## 一、这个项目是什么

- **前端**：Next.js 16（App Router）+ React 19 + Tailwind CSS v4，UI 是一个可拖拽 Card 组成的个人主页 + 博客列表 + 文章详情 + 富文本写文章页面。
- **内容存储**：全部是仓库里的静态文件，没有后端、没有数据库。
  - 文章：`public/blogs/<slug>/index.md`（正文）+ `config.json`（标题/标签/日期/封面等）。
  - 文章索引：`public/blogs/index.json`，分类：`public/blogs/categories.json`。
  - 其他内容区（关于、博主、图片、项目、分享、代码片段）分别放在 `src/app/<分区>/list.json`。
  - 站点配置：`src/config/site-content.json`（站点信息、主题色、背景、社交按钮等）。
- **编辑/发布机制**：网站里点「编辑」→ 导入你的 GitHub 私钥 → 前端用私钥签发 JWT 换取 GitHub token → 直接把新内容提交到 GitHub 仓库 → 部署平台自动重新构建上线。

**一句话总结**：网站、内容、仓库都是属于你的，作者只提供了这套「前端直接操作 GitHub 仓库」的框架。

---

## 二、环境准备

1. 安装 [Node.js](https://nodejs.org/)（建议 18+，项目目标 ES2017 起步）。
2. 安装 pnpm（本项目锁定 pnpm，见 `.npmrc` 和 `pnpm-lock.yaml`）：
   ```bash
   npm install -g pnpm
   ```
3. 一个 GitHub 账号，以及一个用来存放你博客的仓库（可以 Fork 本仓库，也可以新建后把代码推上去）。

---

## 三、本地启动

```bash
# 1. 安装依赖
pnpm i

# 2. 启动开发服务器（端口 2025）
pnpm dev
```

浏览器打开 **http://localhost:2025** 就能看到网站。

其他命令（一般用不到，但要知道）：

```bash
pnpm build      # 标准 Next.js 生产构建
pnpm start      # 运行上面的构建产物
pnpm build:cf   # 构建 Cloudflare Workers 产物
pnpm preview    # 本地预览 Cloudflare 产物
pnpm deploy     # 部署到 Cloudflare
```

> 本地能预览的只是**已经存在于仓库里的内容**。想在前端「编辑并保存」，必须先完成第五步（配置 GitHub App + 私钥），因为保存动作是直接往 GitHub 仓库提交的。

---

## 四、部署

两个平台都支持，任选其一。

### 方案 A：Vercel（最简单）

1. 到 [vercel.com](https://vercel.com) 新建 Project → Import 你的仓库。
2. 不用改任何构建配置，直接点 Deploy（框架会自动识别 Next.js）。
3. 约 60 秒部署完成，得到一个 `https://xxx.vercel.app` 域名。

### 方案 B：Cloudflare Workers（本项目默认配置）

项目已内置 `wrangler.toml` 和 `@opennextjs/cloudflare` 配置：

```bash
pnpm build:cf
pnpm deploy      # 需要先 wrangler login
```

## 五、把博客改成你自己的（核心步骤）

这一步让「网站前端」知道应该往**哪个 GitHub 仓库**写内容，以及用**什么身份**写。

### 5.1 创建 GitHub App 并授权你的仓库

1. 打开 GitHub → 右上角头像 → **Settings** → 左下角 **Developer settings** → **GitHub Apps** → **New GitHub App**。
2. 填写：
   - **GitHub App name**：随便起（如 `my-blog-editor`）。
   - **Homepage URL**：随便填。
   - **Webhook**：关闭（不需要）。
   - **Permissions → Repository permissions → Contents**：设为 **Read and write**（这是唯一必须的权限）。
3. 点击 **Create GitHub App**。
4. 创建后会提示生成 **Private Key**，点击生成并下载 `.pem` 文件（**妥善保管，不要上传到公开仓库**）。同时记下页面上的 **App ID**。
5. 到 App 的 **Install App** 页面，点击 **Install**，**只授权你存放博客的那一个仓库**（这一步务必选「Only select repositories」，别给所有仓库）。

### 5.2 让前端知道目标仓库

有两种方式，二选一：

**方式一：设置环境变量（推荐）**

在部署平台（Vercel / Cloudflare）的项目设置里，添加环境变量：

| 变量名 | 说明 | 示例 |
|---|---|---|
| `NEXT_PUBLIC_GITHUB_OWNER` | 你的 GitHub 用户名 | `yourname` |
| `NEXT_PUBLIC_GITHUB_REPO` | 博客仓库名 | `my-blog` |
| `NEXT_PUBLIC_GITHUB_BRANCH` | 分支 | `main` |
| `NEXT_PUBLIC_GITHUB_APP_ID` | 上面记下的 App ID | `123456` |

设置后需要**重新部署一次**（或 push 一次代码）让环境变量生效。

**方式二：直接改代码（公开仓库无所谓时最省事）**

编辑 `src/consts.ts` 里的 `GITHUB_CONFIG`：

```ts
export const GITHUB_CONFIG = {
  OWNER: 'yourname',      // 你的 GitHub 用户名
  REPO: 'my-blog',        // 你的仓库名
  BRANCH: 'main',
  APP_ID: '123456',       // 你的 GitHub App ID
} as const
```

改完提交代码即可。

### 5.3 导入私钥，开始在前端编辑

1. 打开已部署的网站（或本地 `http://localhost:2025`）。
2. 首页右上角 / 文章页右上角有「编辑」按钮，点击后选择导入你的 **Private Key**（`.pem` 文件）。
3. 导入成功后再点「保存」，改动就会写回 GitHub 仓库。

> 私钥只存在你浏览器本地的 sessionStorage（并用 AES-GCM 加密），刷新页面需重新导入。这是设计使然 —— 私钥代表「谁有权利改这个仓库」。

## 六、用网站前端配置内容（无需改代码）

### 6.1 网站配置（改标题 / 主题色 / 背景 / 社交按钮）

首页有一个不显眼的**配置按钮**，点击打开配置面板，可配置：

- 站点标题、描述、用户名（`src/config/site-content.json` 的 `meta`）。
- 主题色、背景色、art 图片、背景图片。
- 社交按钮（GitHub / 掘金 / 邮箱 / 微博 / B 站等）。
- 头像、Favicon、备案信息等。

### 6.2 写文章

1. 进入「写文章」页面（首页或导航有入口）。
2. 上传封面、填标题/标签/摘要，在编辑器里写 Markdown。
3. 图片管理推荐：先点「+」上传图片（建议压缩到宽度 ≤ 1200px），再把上传好的图片拖进编辑区。
4. 点预览看效果，点保存 → 发布。

> 保存成功后，需要等后台重新构建部署完成，刷新页面才会看到线上更新（本地开发则即时生效）。

### 6.3 删除原作者的内容

拿到一个全新仓库后，第一件事通常是清掉示例内容。你可以在**博客列表页**的「编辑」模式下全选 + 批量删除文章；其他分区（博主、项目、图片、分享、代码片段）同理，在各自页面的编辑模式里删。

## 七、代码级配置（改页面结构）

如果你需要改的是「页面长什么样」，而不是「内容是什么」，才需要动代码。

- **首页**：`src/app/(home)/` 目录。`page.tsx` 是首页入口，下面一堆 `xxx-card.tsx` 对应首页上的每一个 Card（改哪个 Card 就进哪个文件）。
- **首页中间的自我介绍卡片**：`src/app/(home)/hi-card.tsx`。
- **全局布局 / 导航**：`src/layout/index.tsx`（背景、音乐卡片、回到顶部按钮等）、`src/components/nav-card.tsx`。
- **移除「液态玻璃」特效**：在 `src/layout/index.tsx` 里删除两处 `LiquidGrass` 相关代码（`dynamic import` 和 `<LiquidGrass />`）。

## 八、常见问题

- **为什么保存后线上没变化？** —— 保存只是写进了 GitHub 分支，部署平台需要重新构建（push 会触发构建）才会生效，等几十秒再刷新。
- **`.env` / `.pem` 被 gitignore 了，安全吗？** —— 是安全的：`.gitignore` 已忽略 `.env*` 和 `*.pem`，不要把私钥提交进公开仓库。
- **需要数据库吗？** —— 不需要。所有内容都是仓库里的静态文件。
- **本地 `pnpm dev` 能保存吗？** —— 能，只要导入了正确的私钥且 `GITHUB_CONFIG` 指向你自己的仓库。
